# Ternary training on the ANE against the same model trained on the GPU (2026-11-24)

**Question.** Does ternary training on the ANE (fp16 backward) match the same ternary model trained on the GPU with
fp32 gradients, at equal tokens?

**Answer.** Yes, at 2.05M tokens and 3 seeds, once two fixes are in: per-tensor gradient prescales
(`--grad-prescale`) and the forward parameter bound (`--bound`). The ANE path reached 2.245 ± 0.04 against 2.286 ± 0.13
for the GPU path. Without the bound, 2 of 3 seeds diverged.

## Setup
- **Student:** tiny ternary LFM2-shaped model, d = 256, 4 layers (conv, conv, attention, conv), 3.4M trits, tied embedding
  (float-train counts 20.2M parameters in total). Trits trained with TTF, float parameters with Adam.
- **Teacher:** bf16 LiquidAI/LFM2-350M. It writes the training text (one 256-token sequence per update) and scores it.
- **Tokens:** 2,048,000 (8,000 updates of 256), eval every 256k. One run to 8,192,000.
- **Eval:** 8 teacher sequences, fixed (generated under seed 424242 and reseeded with `--seed` afterwards), so every run
  below sees the same held-out set. The number is KL(teacher || student), averaged over those sequences.
- **Hyperparameters ("defaults"):** `--hyper 2e-3,16,1000,1` = Adam rate 2e-3, theta 16, tau 1000, rho x 1.
  Exceptions: `tern-best-s0` uses `1e-3,12.8,1953,0.8`; `fp32-*` are float models with a plain learning rate 3e-3;
  `pbt8-pre` starts member 0 on the defaults and the other 7 at random draws, and mutates them.
- **Binaries:** `float-train` (GPU, MLX autodiff in fp32; `--ternary` = same ternary model and TTF kernel) and `ane-train`
  (`--population 1` unless stated; trunk forward and backward on the ANE in fp16). The ANE runs use the build after the
  overflow-handling fix (2561608); `--bound` is 6d0b2c3.

## Seed summary (defaults, P = 1, held-out KL at 2.05M tokens; sample std, n = 3)

| path | s0 | s1 | s2 | mean ± std |
|---|---|---|---|---|
| ANE ternary, `--grad-prescale --bound` | 2.203 | 2.278 | 2.253 | **2.245 ± 0.04** (0 of 3 diverged) |
| GPU ternary TTF, fp32 gradients | 2.232 | 2.439 | 2.187 | 2.286 ± 0.13 |

The difference of means (0.04) is below either std. The curves cross: the GPU path is ahead at 256k (4.94 to 5.54 against
5.49 to 6.19) and the paths are level by 2.05M. The float (non-ternary) references reach 2.39 to 2.45 at one seed, so
ternary TTF is not worse than float with this budget.

## Ablation: what each fix buys (ANE, defaults, P = 1)

| arm | seeds run | outcome |
|---|---|---|
| base (neither) | 0 | diverged at ~307k tokens (forward overflow: `L3.a_mix` nonfinite as the per-row scales grow) |
| `--grad-prescale` | 0, 1, 2 | s0 finished at 2.150; s1 and s2 diverged at ~1.0M tokens, both in the forward |
| `--grad-prescale --bound` | 0, 1, 2 | 3 of 3 finished: 2.203, 2.278, 2.253 |

Seeds 1 and 2 of base were queued but not run, so the base arm is one seed. The prescale-only seed 0 result (2.150) is the
best single number in the table and probably a lucky survivor. Diagnosis and bound derivation:
[`forward-bounds-2026-11-24.md`](forward-bounds-2026-11-24.md); prescale: [`grad-numerics-2026-11-23.md`](grad-numerics-2026-11-23.md).

PBT-8 with `--grad-prescale` (2.243) did no better than a P=1 bound+prescale run, and four members diverged and were
replaced; it is shown for completeness.

## The old-binary story
Before the overflow-handling fix, ANE P = 1 runs sat at 7.5 to 9.9 at the same budget (defaults 7.517, 39 overflow events,
loss scale sliding to 4 to 8; best settings 6.427; fixed loss scale 2048 never learned, 9.757, 7,634 overflow lines). The cause
was unchecked layer-0 `ds_*`, `dg_*` and `dk*` overflows (token-sum matmuls) going straight into Adam, while each overflow
that was caught halved the loss scale until `gp_*` underflowed. The "float gap is ~4.5 nats" reading in the
notebook (23:00 entry) came from that bug. Those logs (`old-binary/`) are logs only, with no JSONL,
and their eval set differs (the 0-token KL is 9.696 against 9.169), so they are not in the table.

## Caveats
- One machine (M2 Max, macOS 27.2.1). Runs are not bit-reproducible (GPU atomics and chaotic trit flips); a rerun of the
  same seed lands near, not on, these numbers.
- One ANE job and one GPU job ran concurrently, so the wall-clock and tok/s figures in the logs are not throughput
  measurements.
- Three seeds per arm at most; the ANE prescale-only and base arms have fewer. Differences under about 0.3 within a
  seed set are noise.
- PBT selects members on the same 8 held-out sequences it reports, so `pbt8-pre` is optimistic. The P = 1 runs do not select
  on it. The eval set is small (8 sequences of 256 tokens).
- The bound is practical, not a proof: it uses a row-sum factor of 0.1·D instead of the strict worst case, which would put
  the scales below their initial values (see the forward-bounds receipt).
- Attention is still unbounded in the worst case: `e @ (V·2^8)` can exceed fp16 for near-uniform attention unless |v| < 0.5.
  No run hit it, but it is not excluded.
- Backward overflows still occur (60 to 93 events per bound+prescale run); each is detected and skipped, which costs one
  sequence.

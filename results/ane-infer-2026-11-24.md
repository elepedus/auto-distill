# ane-infer: the whole ternarised LFM2-350M on the ANE (2026-11-24, M2 Max)

`ane-infer` runs embedding (GPU) -> 16 decoder layers (ANE, programs chained zero-copy) -> final norm + tied head (GPU).
Weights are the base model ternarised with TWN (`quantise(..., twn: true)` copied from `ternarise`) or `--ckpt DIR`
(`config.json` + `model.safetensors`; per ternary linear `<path>.trits` int8 [N,K], `<path>.scale` fp32 [N], optional
`<path>.colscale` fp32 [K]; every other parameter under its mlx-swift-lm name). The ANE trits, scales, gains and colscales
are `SharedBuffer`s bound once and shared by the prefill and the decode programs.

```
swift build -c release --product ane-infer
.build/out/Products/Release/ane-infer write-ckpt DIR [--colscale]     # TWN checkpoint of the base (test writer; --colscale adds random U(0.5,1.5) input scales)
.build/out/Products/Release/ane-infer [--ckpt DIR] [--text FILE] [--seqs 4] [--reps 20] [--decode-steps 128] [--max-len 512] [--no-decode]
```

Graph changes (`Sources/LFM2ANE`): `layerProgram(..., colscale: Bool = false)` multiplies each linear's input by a slice of one packed
runtime input `cs` (forward only; with the default the emitted programs are unchanged). New `Decode.swift`: `decodeProgram`.

## Parity (4 wikitext-2 sequences, BOS + 255 tokens; reference = same ternary model in MLX on the GPU, fp32 matmuls)

| weights | logits rel-L2 | argmax agreement | KL(GPU ‖ ANE)/token | nonfinite / over 65000 |
|---|---|---|---|---|
| base + TWN | 0.0057 (0.0050-0.0060) | 98.93% | 0.00020 | 0 (max abs y of any layer 1.0) |
| checkpoint with colscale on all 92 linears | 0.0082 (0.0074-0.0091) | 98.83% | 0.00032 | 0 |

The raw TWN model is not recovered (KL to the bf16 base about 7 nats, argmax agreement with the base 4%), as expected before training. This
benchmark measures numerics and speed of the engine, not model quality. ANE and GPU ternary agree as closely as the fp16 ANE allows; the
same ~0.6% as the per-layer receipt (`lfm2-ane-layers-2026-11-23.txt`), compounded over 16 layers without growth.

## Prefill, T = 256 (tok/s over 20 repetitions of one sequence)

| engine | tok/s |
|---|---|
| ANE end to end (embed GPU + 16 layers ANE + bf16 head GPU) | 3873 (66 ms/sequence) |
| ANE embed + 16 layers only | 4659 (55 ms) |
| GPU bf16 base (mlx-swift-lm) | 10853 / 10779 (two passes) |
| GPU ternary (ternarise's TernaryLinear, bf16 matmuls, fp32 elsewhere) | 10330 / 10048 |

Per layer ANE time (ms): conv 3.2, attention 3.7 (all layers listed in the run output; 16 layers sum 54.4 ms). The ANE is about 2.8x
slower than the GPU for prefill on this machine. Programs compile in 7-12 s in total (16 programs, once).

## Decode (single token, max length 512, greedy from BOS, 128 tokens)

Single-token programs (`decodeProgram`) chained zero-copy. State lives in shared buffers: per conv layer the two previous `bx` rows (outputs
`ns0`/`ns1` copied back by the host, 2 KB), per attention layer the post-RoPE K and V caches for 16 heads [16, 512, 64] (the new row
is added in-graph through a one-hot input, and the host writes the output row into the cache), a mask input and cos/sin for the position.

- Parity (teacher-forced, 128 positions, vs GPU ternary prefill logits): rel-L2 0.0064, worst position 0.0109, argmax agreement 100%,
  KL 0.00019 (base + TWN); with colscale: 0.0084, 97.7%, 0.00034.
- Speed: **ANE 28.5-31.5 tok/s** end to end (32-35 ms/token, of which the 16 layers are 30-33 ms, about 2 ms per layer);
  GPU bf16 base 157-223 tok/s; GPU ternary (bf16 matmuls) 110-145 tok/s. The ANE is 5-7x slower than the GPU at decode.
- Not done: handing the state from a prefill to decode (the T=256 programs do not output `bx` or K/V; a decode run starts from BOS, or
  feeds the prompt token by token). The prefill programs would need extra outputs (the conv layers' last two `bx` rows, the post-RoPE K and V
  of each attention layer) written into the decode buffers. Sliding past the max length is also not handled.

## Contention and caveats

- A long GPU training run and other agents' trials were running throughout. GPU numbers are pessimistic and noisy: in one earlier run
  with a neighbour busy, GPU prefill dropped to 4.5k tok/s (ANE 3.5k) and GPU decode to about 145-185 tok/s. Quiet-machine GPU
  numbers will be higher. ANE timings moved less (per layer 3.2-3.7 ms when quiet, up to 5-10 ms during first-run warm-up with others active).
- Every GPU baseline is measured twice in each run (see run output). "GPU ternary" uses bf16 matmuls with fp32 activations, as in
  `ternarise`, so it is not a pure-speed implementation either.
- The ANE stores trits as fp16, so it reads 2 bytes per weight: no bandwidth saving over fp16 weights. The decode figure (about 2 ms per layer for
  roughly 50 MB of weights, ~25 GB/s) says the weights are streamed from memory each token and that this path is far from the GPU's.
  Core ML palettised 2-bit weights (or 1.58-bit packings) would be the route to a real bandwidth win; untested here.
- Embedding and the head run on the GPU (a 134 MB bf16 matrix, 65536 x 1024), and in decode the host does the small state copies; the
  head costs about 11 ms of the 66 ms prefill sequence.
- fp16 hazards remain for trained checkpoints: matmul outputs above ~32752 become inf. The run scans every layer output for nonfinite values.
  The base TWN model's residual stays below 1.0; a trained checkpoint should be re-checked (the scan is part of every run).
